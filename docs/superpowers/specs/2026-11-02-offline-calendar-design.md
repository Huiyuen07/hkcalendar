# 設計：免設定、離線的中式掛曆卡

日期：2026-11-02
狀態：已獲作者同意

## 為甚麼要做

作者喜歡在日曆上看到宜忌，是為了傳統手撕日曆的儀式感，對宜忌內容屬於哪一派沒有偏好。作者最重視兩件事：

1. **資料穩定**：不會因為某個網站或某個整合停止服務，日曆就沒有資料。
2. **用戶免複雜設定**：卡片要可以分享給各個華人地區使用，不需要用戶自己建立 helper、template、script 或 automation。

現在的卡片只負責顯示，所有資料都來自外部：一個自訂整合（老黃曆，作者環境內是更名為 `tgtg` 的舊副本）、三個內建整合、四個 template、一個 script、一個 automation，再加上 jsDelivr 的 OpenCC。任何一環斷掉，卡片就會缺資料；OpenCC 載入失敗時，卡片更會完全不顯示。

## 目標

- 不設定任何實體，加入卡片就能顯示完整日曆：公曆、星期、時間、農曆、宜忌、沖煞、節氣和農曆節日。
- 農曆和宜忌在本機計算，沒有期限，不需要網絡，也不需要定期更新資料。
- 不論用戶身處哪個地區，**所有日曆文字一律顯示繁體中文**。
- 假期由 HA 內建的 Holiday 整合提供，也接受用戶自選的任何 HA 日曆。卡片在程式碼內直接讀取日曆，不經 helper。
- 日程直接讀取用戶揀選的 HA 日曆。

## 非目標

- **卡片不內建任何假期規則。** 港、台、陸及其他地區的假期全部交給 HA 的 Holiday 整合（底層是 `holidays` 函式庫）。這是作者的決定：兩套規則並存時，一旦結果不一致，用戶不知道應該信哪一套；而 HA 的資料有人持續維護，大陸的調休也已包括在內。
- **不提供英文介面**（原 H15 刪除），因為與「一律繁體」矛盾。
- 不追求宜忌內容與現有老黃曆整合一致（作者不在意內容派別）。
- 這一輪不處理字型（H9）、深色模式和響應式版面（H10）、CI 和 HACS（H6）。

## 反目標（做了等於失敗）

- 卡片運作時依賴任何外部網站或 CDN，包括 jsDelivr、Google Fonts 以外的新依賴，以及天文台 API。
- 宜忌資料有期限，過了某一年就沒有資料。
- 某個資料來源失敗時，整張卡片不顯示。缺了假期日曆或日程日曆，其他部分必須照常顯示。
- 畫面上出現簡體字（用戶自己的日程內容和 Holiday 整合的假期名稱除外，見下文）。
- 用戶需要寫 YAML template 或建立 helper 才能使用。

## 已決定的做法

### 農曆和宜忌：打包 `lunar-javascript`

- 使用 [`lunar-javascript`](https://github.com/6tail/lunar-javascript)，版本固定為 1.7.7（MIT）。檔案直接放入 repo 的 `www/`，與卡片放在同一目錄部署，**不經 CDN**。
- 實測結果（2026-10-31 及 2026-11-02）：
  - 抽樣 40 日（包括月頭月尾）的農曆日期與天文台完全一致。
  - 1901、2099、2500、3000 年都能正常計算，沒有期限。
  - `lunar.js` 原檔 436 KB，gzip 後約 112 KB。
  - 2000 至 2099 年間，宜忌一共只用到 114 個詞。單日最多 31 項。
- 它的檔案是 UMD 格式，以 `this` 作為全域根物件。在 ES module 內直接 `import` 時，`this` 是 `undefined`，所以不能直接匯入。建議用同目錄的 classic `<script>` 載入，或在 repo 內加一層包裝。用哪個方法由實作者決定，但必須離線可用，而且載入路徑要以卡片 JS 的位置為基準（與現在載入 CSS 的方法相同）。
- 卡片需要的資料和對應 API（實測可用）：

  | 顯示 | API | 例子 |
  |------|-----|------|
  | 農曆年 | `getYearInGanZhi()` + `getYearShengXiao()` | 丙午(馬)年 |
  | 農曆日期 | `getMonthInChinese()` + `月` + `getDayInChinese()` | 九月廿四、臘月初八 |
  | 宜 / 忌 | `getDayYi()` / `getDayJi()` | 祭祀 沐浴 解除 |
  | 沖煞 | `getDayShengXiao()` + `日沖` + `getDayChongShengXiao()` | 龍日沖狗 |
  | 節氣 | `getJieQi()`（不是節氣當日回傳空字串） | 冬至 |
  | 農曆節日 | `getFestivals()` | 重陽節、七夕節、春節 |

- 農曆月份沿用 lunar-js 的寫法，例如「冬月」「臘月」。這是我的決定。
- 計算日期一律用瀏覽器的本地日期，並以年、月、日數字傳入 `Solar.fromYmd`。不可以再用 `new Date('YYYY-MM-DD')`，它會以 UTC 解析（原 H13）。

### 繁體：內建對照表，移除 OpenCC

- 移除 OpenCC 及其 CDN 載入（原 H2）。
- lunar-js 的輸出是簡體，詞彙是有限集合，所以卡片內建一個繁體對照表，涵蓋：
  - 宜忌詞彙
  - 生肖
  - 農曆月份和日期用字
  - 節氣
  - `getFestivals()` 會出現的節日名稱
  - 「沖」字
- 對照表以「詞」為單位最安全，詞內逐字替換也可以，由實作者決定。
- **必須有測試保證沒有遺漏**：逐日掃描一段長時間（例如 1900 至 2100 年），確認所有輸出經轉換後都沒有對照表以外的簡體字。
- 「沖」維持現在的寫法，不用「衝」。
- 以下兩類文字**不轉換**，原樣顯示：
  - **用戶自己日程的標題**：那是用戶的內容。
  - **Holiday 整合的假期名稱**：涵蓋上百個國家，無法用小表處理。README 要提示用戶在 Holiday 整合中選擇繁體語言，例如香港選 `zh_HK`、台灣和大陸選 `zh_TW`（實測三地都有繁體名稱）。

### 假期：讀取 HA 日曆

- 新選項 `holiday_calendars`：一個或多個 calendar 實體。通常是 Holiday 整合建立的日曆，也可以是用戶自訂的任何日曆。
- 卡片用 `hass.callApi('GET', 'calendars/<entity_id>?start=…&end=…')` 讀取事件。實測作者的 `calendar.hksar` 可以這樣取回繁體名稱的全日事件。
- 判斷規則：
  1. 揀選的假期日曆中，**當日有全日事件**的話，當日就是假期，使用假日顏色，並在當日文字顯示事件名稱。
  2. 星期日一律使用假日顏色。
  3. **大陸的補班日**：Holiday 整合的大陸假期名稱會註明補班日期。例子：2026-02-20 的名稱是「放假日（2026-02-14 補班）」，簡體語言則寫「补班」。卡片解析名稱中的 `（YYYY-MM-DD 補班）` 或 `（YYYY-MM-DD 补班）`，被點名的日子使用工作日顏色，即使當日是星期日。補班日期可能在假期之前或之後幾星期，所以讀取範圍要涵蓋前後一段日子，例如前後各 45 日，實際長度由實作者決定。
- 沒有設定 `holiday_calendars` 時，只有星期日使用假日顏色。
- 讀取失敗（例如網絡、權限問題或實體不存在）時，當作當日沒有假期，卡片其他部分照常顯示，錯誤只寫入 console。
- 不再使用 `workday_entity`。

### 日程：讀取 HA 日曆

- 新選項 `event_calendars`：一個或多個 calendar 實體（原 H8）。
- 讀取當日事件，格式沿用現在 script 的做法：
  - 有時間的事件寫成 `hh:mm AM 標題`，全日事件只寫標題。
  - 多個日曆的事件合併，按開始時間排序。
  - 事件之間以 `  |  ` 分隔，沒有事件時顯示「無日程」。
- 沿用現在的滾動顯示。
- 定期重新讀取，間隔由實作者決定，建議不長於 15 分鐘。跨過午夜時要立即重新讀取。
- 取代 `input_text.calendar`（上限 255 字）、`today_s_itinerary` script 和每 5 分鐘一次的 automation。

### 卡面內容

版面維持現在的手撕日曆樣式。

- **保留英文裝飾**：卡頂的英文月份（例如 November），以及「星期一 Monday」中英並列的寫法。這是作者的決定：英文是傳統手撕日曆的特色。
- **公曆和時間**：取自瀏覽器時鐘，每分鐘更新，格式沿用 `04:48 PM`。
- **當日文字**：依次列出以下各項，以 ` ｜ ` 分隔，沒有的項目略過：
  1. 農曆節日或節氣
  2. 假期名稱，多個時全部列出
  3. 沖煞

  例子：「重陽節 ｜ 牛日沖羊」。
- **宜、忌各只顯示頭四項**（原 H12）。這是作者的決定，美感優先：
  - 每項一行，最多四行，按 lunar-js 回傳的次序取頭四項。
  - 字體大小和區塊高度維持現在的樣式，不縮字、不分欄，也不顯示「還有幾項」之類的提示。
  - 不足四項時照實顯示；沒有項目時顯示「無」。
- 所有由資料產生的文字一律用 `textContent` 寫入，不再用 `innerHTML`（原 H14）。

### 設定和編輯器

- 所有選項都是可選的：

  | 選項 | 說明 | 預設值 |
  |------|------|--------|
  | `holiday_calendars` | 假期日曆，一個或多個 | 無 |
  | `event_calendars` | 日程日曆，一個或多個 | 無 |
  | `holidayColor` | 假日顏色 | `#CC0000` |
  | `workdayColor` | 工作日顏色 | `#006400` |

- `setConfig` 不再因為缺少實體而拋出錯誤。
- **不保留舊版相容**。這是作者的決定：作者會直接部署新版，同時棄置舊設定。
  - 舊版選項（例如 `date_entity`、`yi_entity`、`workday_entity`、`rolling_text_entity`）連同相關程式碼一併刪除。
  - 卡片不會特別處理這些舊選項，也不會發出提示。
- **卡片編輯器**（原 H5）：
  - 使用 HA 內建的表單元件（例如 `ha-form`，配合 calendar 實體選擇器，並允許多選）。
  - 修改時要發出 `config-changed` 事件，否則改了也存不到。
  - 註冊 `window.customCards`，令卡片出現在卡片選擇器。
- `getStubConfig()` 回傳空設定，或只包含顏色。

### 授權

- 加入 lunar-javascript 的 MIT 授權聲明，例如放在 `www/` 內與檔案同行，或寫入 `THIRD_PARTY_NOTICES`。打包它必須附上這份聲明。
- 本專案自身的授權（原 H1）不在這一輪範圍內。

### 測試

- `npm test` 移除固定的 `TZ=Asia/Hong_Kong`，並在至少一個非香港時區下通過（例如 `America/New_York`）。
- 固定日期的黃金測試，鎖定農曆、宜忌、沖煞、節氣和節日的輸出。用來在升級 lunar-js 時察覺內容改變。可用的參考日子：2026-11-02、2026-10-18（重陽）、2026-12-22（冬至）、2027-02-06（春節）。
- 繁體轉換的遺漏掃描，見上文。
- 宜忌只取頭四項：多於四項時只顯示頭四項，次序不變；不足四項時照實顯示；沒有項目時顯示「無」。
- 假期判斷：全日事件、星期日、補班星期日、沒有設定日曆，以及讀取失敗。
- 日程格式：有時間和全日混合、多個日曆、沒有事件。
- 編輯器會發出 `config-changed`。

## 完成後：作者環境遷移

第 1 步由作者自己直接做。之後由 Claude 協助的步驟會改動作者的 HA，**每一步動手前都要先問作者**。

1. 作者自行部署新版本，把 Lovelace 資源指向 `/local/hkcalendar/chinese-calendar-card.js`（原 H0）。
2. 把作者 dashboard 的卡片設定整份換成新選項，舊選項全部刪除：
   - `holiday_calendars: [calendar.hksar]`
   - `event_calendars`：用現在 `today_s_itinerary` script 讀取的日曆，遷移時再確認是哪一個。
3. 確認新卡運作正常後，才移除以下項目（原 H00）：
   - `tgtg` 整合
   - 已安裝但未設定的 HACS 版老黃曆
   - `sensor.today`、`sensor.lunar_year`、`sensor.lunar_date`、`binary_sensor.hksar_workday` 四個 template
   - `input_text.calendar`、`today_s_itinerary` script，以及每 5 分鐘一次的 automation

   移除前要先檢查有沒有其他地方用到這些實體。
4. `calendar.nong_li` 的 404 問題（原 H000）不用處理，因為農曆節日已改由 lunar-js 提供。

## 審閱後補充的決定（我的決定）

- **繁體寫法**：跟從舊版 OpenCC `cn→tw` 的做法。實際受影響的只有「启钻」一詞，寫作「啟鑽」。
- **多個假期日曆衝突**：任何一個日曆標明當日是假期，就使用假日顏色。只有在沒有任何日曆標明假期時，補班日才會把星期日改為工作日顏色。
- **跨日事件**：
  - 跨越今日的全日事件，算作當日的事件或假期。
  - 有時間的事件，只要與今日重疊就列出：今日開始的寫出開始時間，之前已開始的只寫標題。
- **補班日的文字**：補班日在當日文字中加上「補班」。
- **HA 版本**：以作者使用的 HA 2026.10 為基準，不保證支援更舊的版本。

## 留給實作者決定

- 繁體對照表的結構，以詞為單位或逐字替換。
- 假期讀取的前後範圍，以及日程重新讀取的間隔。
- 編輯器的實作細節。
- 檔案如何拆分，例如對照表是否獨立成檔。
